# 주석 규칙

## 원칙

**주석은 기본적으로 달지 않는다.** 이름과 구조로 설명되게 코드를 고치는 쪽이 먼저다.
주석은 지워지지 않고 남아 코드와 어긋나기 시작하는 순간부터 거짓말이 된다.

주석을 달기 전에 순서대로 시도한다.

1. 변수·메서드 이름을 정확하게 바꾼다
2. 긴 메서드를 이름 있는 private 메서드로 쪼갠다
3. 그래도 **"왜"** 가 안 드러나면 그때 한 줄 단다

## 달아도 되는 주석 — "왜"

코드를 읽어도 알 수 없는 **의도·배경·함정**만 적는다.

```java
// 우표 후보가 없으면 완료 상태로 만들 수 없다. SUBMITTED 로 남겨 두고 재처리에 맡긴다.
if (stamp.isEmpty()) {
    return;
}
```

```java
// 시드 실패로 기동을 막으면 무중단 배포가 통째로 멈춘다. 로그만 남기고 기동은 이어간다.
catch (Exception e) {
    log.error("우표 시드에 실패했다.", e);
}
```

## 지워야 할 주석 — "무엇"

```java
// 사용자를 조회한다                      ← 코드가 이미 그렇게 읽힌다
Users user = userRepository.findById(userId)...

/**
 * Skeleton 전체 조회                     ← 메서드명이 곧 설명이다
 */
public SkeletonListResponse getSkeletons() { ... }

// 편지 ID                                ← 필드명과 같은 말
private Long letterId;
```

- 코드를 한국어로 옮겨 적은 주석
- 구획을 나누는 장식 주석 (`// ===== 조회 =====`)
- 주석 처리한 옛 코드 — 지운다. 필요하면 git 이 갖고 있다.
- 변경 이력 (`// 2026-08-22 수정`) — git 이 갖고 있다.

## Javadoc

**공개 API 의 계약이 시그니처만으로 드러나지 않을 때만** 쓴다. 그 외에는 달지 않는다.

| 쓴다 | 쓰지 않는다 |
|---|---|
| 반환값이 `null` 일 수 있는 조건 | Controller·Service 의 일반 메서드 |
| 호출 순서·전제 조건이 있을 때 | 엔티티 getter/setter, DTO |
| 던지는 예외의 발생 조건이 이름에서 안 보일 때 | 이름으로 충분히 설명되는 메서드 |

메서드 설명만 반복하는 `@param` · `@return` 은 쓰지 않는다.

## 다른 문서를 참조하지 않는다

**주석에서 다른 문서의 섹션·항목 번호를 가리키지 않는다.**

```java
// 세그먼트 생성은 서버 책임이다 (기능명세 3.5.3)          ← 금지
// 후보에서 기본 우표를 뺀다 (ERD A9-1)                    ← 금지
// TODO: 교체 방법은 docs/남은것.md 참고                   ← 금지
```

문서는 개편되고 번호는 밀린다. 그때 코드 주석까지 따라 고치는 사람은 없다.
남는 건 **존재하지 않는 절을 가리키는 주석**이고, 읽는 사람은 그걸 확인하러 문서를 뒤지느라 시간을 쓴다.

대신 **주석 한 줄이 그 자체로 완결되게** 쓴다.

```java
// 세그먼트 생성은 LLM 이 아니라 서버 책임이다. LLM 출력이 어떻든 조각을 이으면 원문·교정문과 일치해야 한다.
```
