# 프론트엔드 변경 사항 — 2026-08-30

## 1. 요약

- API 엔드포인트, 요청 형식, 정상 응답 필드명·타입은 변경되지 않았습니다.
- 편지 조회 응답의 `Status` enum에 `FEEDBACK_FAILED`가 추가되었습니다.
- `FEEDBACK_FAILED`는 API 오류가 아니라 정상 응답의 `status` 값입니다.
- 프론트에서는 `FEEDBACK_FAILED`를 준비 중 상태와 구분하고 자동 새로고침을 중단해야 합니다.
- 모든 `/api/**` 요청에 IP 기준 분당 120회 제한이 추가되었습니다.
- `POST /api/v1/letters`에는 사용자 ID 기준 분당 5회 제한이 추가되었습니다.
- 제한 초과 시 `429`와 `COMMON_004`가 내려옵니다.

## 2. API 변동 사항

| Method | 엔드포인트 | 영향 필드 | 변동 사항 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/letters` | `letters[].status` | `FEEDBACK_FAILED`가 내려올 수 있음 |
| `GET` | `/api/v1/letters/{letterId}` | `status`, `feedback` | `status`가 `FEEDBACK_FAILED`일 수 있으며 이때 `feedback`은 `null` |
| 전체 | `/api/**` | 실패 응답 | IP 기준 분당 120회 초과 시 `429` / `COMMON_004` |
| `POST` | `/api/v1/letters` | 실패 응답 | 사용자 ID 기준 분당 5회 초과 시 `429` / `COMMON_004` |

### 2-1. `/api/v1/letters`

편지 목록의 `letters[].status`에 `FEEDBACK_FAILED`가 내려올 수 있습니다.

```json
{
    "letters": [
        {
            "letterId": 15,
            "date": "2026-08-30",
            "summary": "I wrote a letter today...",
            "status": "FEEDBACK_FAILED",
            "isRead": false,
            "stampImage": "https://{host}/dear-jolly-stamps/stamp/soon.png"
        }
    ],
    "hasNext": false
}
```

`FEEDBACK_FAILED` 카드 처리 규칙:

- 준비 중 애니메이션을 종료합니다.
- 자동 새로고침과 상태 재확인을 중단합니다.
- 피드백 생성 실패 안내를 표시합니다.
- 상세 화면 진입을 막습니다.
- `isRead == false`여도 미열람 빨간 점을 표시하지 않습니다.
- `stampImage`는 상태에 따라 직접 조합하지 않고 응답 URL을 그대로 사용합니다.

자동 새로고침 대상은 `SUBMITTED`, `FEEDBACK_IN_PROGRESS` 두 상태뿐입니다. 상태 변경 전용 API는 없습니다.

### 2-2. `/api/v1/letters/{letterId}`

상세 응답의 `status`에도 `FEEDBACK_FAILED`가 내려올 수 있습니다.

```json
{
    "letterId": 15,
    "date": "2026-08-30",
    "originalContent": "I wrote a letter today...",
    "status": "FEEDBACK_FAILED",
    "stampImage": "https://{host}/dear-jolly-stamps/stamp/soon.png",
    "feedback": null
}
```

- HTTP 상태는 오류가 아닌 `200 OK`입니다.
- `feedback`은 `null`입니다.
- `feedback`은 `FEEDBACK_COMPLETED` 상태에서만 값이 있습니다.
- `SUBMITTED`, `FEEDBACK_IN_PROGRESS`, `FEEDBACK_FAILED` 상태에서는 `feedback`이 `null`입니다.

### 2-3. 요청 제한 변동 사항

- 모든 `/api/**` 요청은 클라이언트 IP 기준 분당 120회까지 허용됩니다.
- `POST /api/v1/letters`는 인증된 사용자 ID 기준 분당 5회까지 허용됩니다.
- `POST /api/v1/letters`에는 IP 기준 공통 제한과 사용자별 편지 작성 제한이 모두 적용됩니다.
- 제한 횟수는 고정된 1분 단위로 계산됩니다.
- 둘 중 하나라도 제한을 초과하면 HTTP `429 Too Many Requests`와 `COMMON_004`를 반환합니다.
- 앱은 `429` 응답을 받으면 즉시 반복 요청하지 말고 잠시 기다린 후 다시 시도해야 합니다.

```json
{
    "status": 429,
    "code": "COMMON_004",
    "message": "요청이 너무 많습니다. 잠시 후 다시 시도해주세요."
}
```

| 적용 대상 | 식별 기준 | 분당 허용 횟수 | 초과 응답 |
| --- | --- | ---: | --- |
| 모든 `/api/**` 요청 | 클라이언트 IP | 120회 | `429` / `COMMON_004` |
| `POST /api/v1/letters` | 인증된 사용자 ID | 5회 | `429` / `COMMON_004` |

## 3. 최종 enum 종류 (`Status`)

| 값 | 의미 | 프론트 처리 |
| --- | --- | --- |
| `SUBMITTED` | 피드백 작업 대기 | 준비 중 표시, 상세 진입 차단, 상태 재확인 |
| `FEEDBACK_IN_PROGRESS` | 피드백 생성 중 | 준비 중 표시, 상세 진입 차단, 상태 재확인 |
| `FEEDBACK_COMPLETED` | 피드백 생성 완료 | 완료 우표 표시, 상세 진입 허용 |
| `FEEDBACK_FAILED` | 피드백 생성 최종 실패 | 실패 안내, 상세 진입 차단, 상태 재확인 중단 |

권장 분기:

```text
SUBMITTED | FEEDBACK_IN_PROGRESS -> 준비 중
FEEDBACK_COMPLETED               -> 완료
FEEDBACK_FAILED                  -> 실패
```
