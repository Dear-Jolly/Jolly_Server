# 프론트엔드 변경 사항 — 2026-08-30

## 요약

- **API 스펙은 일부 변경되었습니다.** 엔드포인트와 응답 구조는 그대로지만, 기존 편지 상태 enum에 `FEEDBACK_FAILED`가 추가되었습니다.
- `FEEDBACK_FAILED`는 API 오류가 아니라 편지 조회 성공 응답의 `status` 값으로 내려옵니다.
- 프론트에서는 이 상태를 준비 중 상태와 구분하고, 자동 새로고침을 중단해야 합니다.
- 모든 API에 분당 120회 제한이 적용되고, `POST /api/v1/letters`는 사용자당 분당 5회 제한이 추가됩니다.
- 제한을 초과하면 HTTP 429와 `COMMON_004`를 반환합니다.

## API 스펙 변경 여부

| 구분 | 변경 여부 | 내용 |
| --- | :---: | --- |
| 엔드포인트 | 변경 없음 | 추가·삭제·경로 변경 없음 |
| 요청 스펙 | 변경 없음 | body, path variable, query parameter 변경 없음 |
| 응답 구조 | 변경 없음 | 필드명과 타입 변경 없음 |
| 응답 enum | **변경됨** | `Status`에 `FEEDBACK_FAILED` 추가 |
| HTTP 상태 코드·에러 코드 | **변경됨** | 요청 제한 초과 시 `429 COMMON_004` 추가. `FEEDBACK_FAILED`는 여전히 `200 OK` 응답에 포함 |

## 영향 API

| Method | 엔드포인트 | 영향 필드 | 변경 내용 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/letters` | `letters[].status` | `FEEDBACK_FAILED`가 내려올 수 있음 |
| `GET` | `/api/v1/letters/{letterId}` | `status`, `feedback` | `status`가 `FEEDBACK_FAILED`일 수 있으며 이때 `feedback`은 `null` |

`POST /api/v1/letters`를 포함한 나머지 API의 요청·응답 계약은 변경되지 않았습니다.

## 영향받는 API

### `GET /api/v1/letters`

편지 목록의 `letters[].status`에 `FEEDBACK_FAILED`가 내려올 수 있습니다.

```json
{
    "letters": [
        {
            "letterId": 15,
            "date": "2026-08-30",
            "summary": "I wrote a letter today...",
            "status": "FEEDBACK_FAILED",
            "isRead": false,
            "stampImage": "https://{host}/dear-jolly-stamps/stamp/soon.png"
        }
    ],
    "hasNext": false
}
```

`FEEDBACK_FAILED` 카드 처리 규칙:

- 준비 중 애니메이션을 종료합니다.
- 화면 재진입이나 새로고침 시 상태 변화를 자동으로 계속 확인하지 않습니다.
- 피드백 생성 실패 안내를 표시합니다.
- 상세 화면 진입을 막습니다.
- `isRead == false`여도 미열람 피드백을 뜻하지 않으므로 빨간 점을 표시하지 않습니다.
- `stampImage`는 상태로 직접 조합하지 말고 응답 URL을 그대로 사용합니다.

자동 새로고침 대상은 `SUBMITTED`, `FEEDBACK_IN_PROGRESS` 두 상태뿐입니다. 상태 변경 전용 API는 없습니다.

## 요청 제한 및 `COMMON_004`

- 모든 `/api/**` 요청은 클라이언트 IP 기준 분당 120회까지 허용됩니다.
- `POST /api/v1/letters`는 인증된 사용자 ID 기준 분당 5회까지 허용됩니다.
- 제한 초과 시 HTTP 429와 `COMMON_004`를 반환합니다. 앱은 즉시 반복 요청하지 말고 잠시 기다린 후 재시도합니다.

### `GET /api/v1/letters/{letterId}`

상세 응답의 `status`에도 `FEEDBACK_FAILED`가 내려올 수 있습니다. 이 경우에도 HTTP 상태는 `200 OK`이며 `feedback`은 `null`입니다.

```json
{
    "letterId": 15,
    "date": "2026-08-30",
    "originalContent": "I wrote a letter today...",
    "status": "FEEDBACK_FAILED",
    "stampImage": "https://{host}/dear-jolly-stamps/stamp/soon.png",
    "feedback": null
}
```

`feedback`은 `FEEDBACK_COMPLETED`일 때만 값이 있습니다. `SUBMITTED`, `FEEDBACK_IN_PROGRESS`, `FEEDBACK_FAILED`에서는 `null`입니다.

## `Status` enum 최종 정의

| 값 | 의미 | 프론트 처리 |
| --- | --- | --- |
| `SUBMITTED` | 피드백 작업 대기 | 준비 중 표시, 상세 진입 차단, 상태 재확인 |
| `FEEDBACK_IN_PROGRESS` | 피드백 생성 중 | 준비 중 표시, 상세 진입 차단, 상태 재확인 |
| `FEEDBACK_COMPLETED` | 피드백 생성 완료 | 완료 우표 표시, 상세 진입 허용 |
| `FEEDBACK_FAILED` | 피드백 생성 최종 실패 | 실패 안내, 상세 진입 차단, 상태 재확인 중단 |

권장 분기 예시:

```text
SUBMITTED | FEEDBACK_IN_PROGRESS -> 준비 중
FEEDBACK_COMPLETED               -> 완료
FEEDBACK_FAILED                  -> 실패
```

## 데이터 관련 주의사항

- 이번 변경이 적용되는 환경에서는 기존 편지와 피드백 데이터가 한 번 초기화됩니다.
- 애플리케이션 기동 시 생성되던 더미 편지 데이터도 제거되었습니다.
- 따라서 배포 직후 기존 사용자의 편지 목록이 빈 배열로 보일 수 있으며, 이는 목록 API 오류가 아닙니다.
